= リカバリの開始を選択して StorageGRID ストレージノードを構成します
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
ストレージノードを交換したら、 Grid Manager で Start Recovery を選択して、障害が発生したノードの代わりとして新しいノードを設定する必要があります。

.開始する前に
* Grid Managerにサインインしておきますlink:../admin/web-browser-requirements.html["サポートされている Web ブラウザ"]。
* あなたはを持っていますlink:../admin/admin-group-permissions.html["Maintenance権限またはRoot Access権限"]。
* プロビジョニングパスフレーズを用意します。
* 交換用ノードの導入と設定を完了しておきます。
* イレイジャーコーディングデータの修復ジョブの開始日を確認しておきます。


.タスクの内容
ストレージノードが Linux ホストにコンテナとしてインストールされている場合は、次のいずれかに該当する場合にのみこの手順を実行する必要があります。

* フラグを使用し `--force`てノードをインポートするか、または `storagegrid node force-recovery _node-name_`
* ノードの完全な再インストールを実行するか、 /var/local をリストアする必要がありました。


.手順
. プライマリ管理ノードにログインします。プライマリ管理ノードが利用できない場合は、プライマリ以外の管理ノードが存在すればそちらを使用してください。
. グリッドマネージャから、*メンテナンス* > *タスク* > *ノード復旧*を選択します。
. リカバリするグリッドノードを Pending Nodes リストで選択します。
+
ノードに障害が発生するとリストに表示されますが、ノードを再インストールしてリカバリの準備ができるまでは選択できません。

. *Provisioning passphrase* を入力してください。
. 「リカバリを開始」をクリックします。
. *Maintenance* > *Tasks* > *Node recovery* を選択し、復旧の進捗状況を確認することで、復旧の進行状況を監視します。
+
** グリッドノードが「手動ステップ待ち」段階に達した場合は、link:../maintain/remounting-and-reformatting-storage-volumes-manual-steps.html["ストレージボリュームを手動で再マウントおよび再フォーマットする"]。手動手順が完了したら、link:../maintain/restoring-object-data-to-storage-volume.html["オブジェクトデータをボリュームに復元する"]に進みます。
** グリッドノードの復旧が「手動手順待ち」の段階を経ずに「進行中」から「復旧済み」に移行した場合、それ以上の操作は必要ありません。
+
[NOTE]
====
復旧処理のどの段階でも、*リセット*を選択して新しい復旧を開始できます。手順をリセットするとノードが不確定な状態になることを示すダイアログボックスが表示されます。

手順をリセットした後に復旧を再試行する場合は、アプライアンスノードを次のようにプリインストール状態に復元する必要があります。

*** * vmware * ：導入した仮想グリッドノードを削除します。その後、リカバリを再開する準備ができたら、ノードを再導入します。
*** * Linux *：Linuxホストで次のコマンドを実行してノードを再起動します。 `storagegrid node force-recovery _node-name_`
